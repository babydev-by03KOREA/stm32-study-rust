## 2. 핵심 개념

### GPIO (General Purpose Input/Output)
- 칩 둘레의 핀(PA0, PC13 등)을 입력이나 출력으로 정해서 쓰는 기능
- 출력: 핀에 1(3.3V) 또는 0(0V)을 내보냄 → LED
- 입력: 핀의 전압이 높은지 낮은지 읽음 → 버튼
- 같은 핀을 GPIO 대신 다른 기능(UART, SWD 등)으로 바꿀 수도 있음
    - 예: SYS → Debug: Serial Wire를 켜면 PA13, PA14가 디버거 전용이 됨

### 풀업 / 풀다운
- 버튼을 안 누를 때 핀이 공중에 떠서 값이 흔들리는 걸 막으려고 기본값을 잡아 주는 것
- 풀업: 기본 1 → 버튼을 GND에 연결하면 누를 때 0
- 풀다운: 기본 0 → 버튼을 3.3V에 연결하면 누를 때 1
- 그래서 풀업 + GND 배선에서는 `if (!HAL_GPIO_ReadPin(...))`처럼 `!`가 붙음

### Active-Low
- 블루필 PC13 LED는 0을 써야 켜지고 1을 써야 꺼짐
- 회로가 어떻게 연결됐는지에 따라 0/1의 의미가 바뀜 → 회로도를 읽어야 하는 이유

### 레지스터
- 하드웨어를 제어하는 특정 메모리 주소. 비트 하나하나가 설정 하나
- 오늘 쓴 레지스터 (RM0008 기준)

| 레지스터 | 주소 | 역할 |
|---|---|---|
| RCC_APB2ENR | 0x40021018 | 주변장치 클럭 켜기 (bit2 = GPIOA, bit4 = GPIOC) |
| GPIOA_CRL | 0x40010800 | PA0~PA7 모드 설정 (핀당 4비트) |
| GPIOA_IDR | 0x40010808 | PA 입력 값 읽기 |
| GPIOA_ODR | 0x4001080C | 입력 모드에서는 풀업(1)/풀다운(0) 선택 |
| GPIOC_CRH | 0x40011004 | PC8~PC15 모드 설정 (PC13 = 20~23번 비트) |
| GPIOC_ODR | 0x4001100C | PC 출력 값 |
| GPIOC_BSRR | 0x40011010 | 핀 켜기(0~15번 비트)/끄기(16~31번 비트) 전용 |

- STM32는 전력 절약을 위해 모든 주변장치 클럭이 꺼진 채 시작 → GPIO 쓰기 전에 클럭부터 켜야 함
- `volatile`: 하드웨어가 값을 바꿀 수 있으니 컴파일러가 최적화로 지우지 말라는 표시
- ODR `|=` 는 읽기 → 수정 → 쓰기 3단계라 인터럽트가 끼어들면 꼬일 수 있음. BSRR은 한 번 쓰기로 끝나서 안전 (Java의 `AtomicInteger`와 같은 이유)

### HAL (Hardware Abstraction Layer)
- 레지스터 조작을 함수로 감싼 ST 공식 라이브러리 (`HAL_GPIO_TogglePin` 등)
- 내부로 따라 들어가면 결국 레지스터에 비트를 씀

| 계층 | 하는 일 | Spring 비유 |
|---|---|---|
| 레지스터 직접 접근 | 주소에 비트를 직접 씀 | JDBC로 SQL 직접 |
| LL (Low-Layer) | 레지스터를 얇게 감싼 함수 | JdbcTemplate |
| HAL | 기능 단위로 크게 감싼 함수 | Spring Data JPA |
| CubeMX 생성 코드 | 설정대로 초기화 코드 자동 생성 | Spring Boot 자동 설정 |

### CubeMX와 .ioc
- 칩 그림에서 핀과 기능을 클릭으로 설정하면 초기화 코드(`MX_GPIO_Init` 등)를 생성
- `.ioc` = 그 설정 파일
- User Label을 `GPIO_LED`로 붙이면 `main.h`에 이렇게 생성됨 (`GPIO_LED` 자체는 없음)
  ```c
  #define GPIO_LED_Pin        GPIO_PIN_13
  #define GPIO_LED_GPIO_Port  GPIOC
  ```
- 직접 쓰는 코드는 반드시 `/* USER CODE BEGIN x */` ~ `/* USER CODE END x */` 사이에. 밖에 쓰면 재생성 시 삭제됨
    - `while` 루프 안 코드는 `USER CODE BEGIN 3` 다음에 작성

### 클럭 (Clock Configuration 탭)
- CPU가 명령을 실행하는 박자
- HSI: 칩 내부 8MHz (기본값, 오차 1~2%)
- HSE: 보드의 8MHz 크리스탈 (정확함)
- PLL: 배수기. 8MHz × 9 = 72MHz (F103 최대)
- 기본값(HSI 8MHz)으로도 동작에는 문제없음. `HAL_Delay`도 현재 클럭 기준으로 계산됨
- 강의에서는 아직 안 다룸 → UART, 타이머 배울 때 다시 나옴

## 3. 네 가지 방식 비교

### 3-1. C 레지스터 — LED 깜빡이기

```c
#include <stdint.h>

#define RCC_APB2ENR (*(volatile uint32_t *)0x40021018)
#define GPIOC_CRH   (*(volatile uint32_t *)0x40011004)
#define GPIOC_ODR   (*(volatile uint32_t *)0x4001100C)

int main(void)
{
    RCC_APB2ENR |= (1 << 4);        // GPIOC 클럭 켜기
    GPIOC_CRH &= ~(0xF << 20);      // PC13 설정 지우기
    GPIOC_CRH |=  (0x2 << 20);      // 출력 2MHz, push-pull

    for (;;)
    {
        GPIOC_ODR ^= (1 << 13);     // 뒤집기
        for (volatile uint32_t i = 0; i < 200000; i++);
    }
}
```

### 3-2. C HAL — 버튼으로 LED 켜기 (CubeMX 생성 프로젝트)

```c
  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    if (!HAL_GPIO_ReadPin(GPIO_SW_GPIO_Port, GPIO_SW_Pin)) {
        HAL_GPIO_WritePin(GPIO_LED_GPIO_Port, GPIO_LED_Pin, GPIO_PIN_RESET);
    } else {
        HAL_GPIO_WritePin(GPIO_LED_GPIO_Port, GPIO_LED_Pin, GPIO_PIN_SET);
    }
  }
  /* USER CODE END 3 */
```

### 3-3. Rust 레지스터 — 버튼으로 LED 켜기

```rust
#![no_std]
#![no_main]

use core::ptr::{read_volatile, write_volatile};
use cortex_m_rt::entry;
use defmt::info;
use {defmt_rtt as _, panic_probe as _};

const RCC_APB2ENR: *mut u32 = 0x4002_1018 as *mut u32;
const GPIOA_CRL: *mut u32 = 0x4001_0800 as *mut u32;
const GPIOA_IDR: *const u32 = 0x4001_0808 as *const u32;
const GPIOA_ODR: *mut u32 = 0x4001_080C as *mut u32;
const GPIOC_CRH: *mut u32 = 0x4001_1004 as *mut u32;
const GPIOC_BSRR: *mut u32 = 0x4001_1010 as *mut u32;

#[entry]
fn main() -> ! {
    info!("button demo start");

    unsafe {
        let apb2 = read_volatile(RCC_APB2ENR);
        write_volatile(RCC_APB2ENR, apb2 | (1 << 2) | (1 << 4)); // GPIOA, GPIOC 클럭

        let mut crl = read_volatile(GPIOA_CRL);
        crl &= !(0xF << 0);
        crl |= 0x8 << 0;                                          // PA0 입력 + 풀업/풀다운
        write_volatile(GPIOA_CRL, crl);

        let odr = read_volatile(GPIOA_ODR);
        write_volatile(GPIOA_ODR, odr | (1 << 0));                // 풀업 선택

        let mut crh = read_volatile(GPIOC_CRH);
        crh &= !(0xF << 20);
        crh |= 0x2 << 20;                                         // PC13 출력
        write_volatile(GPIOC_CRH, crh);
    }

    let mut was_pressed = false;
    loop {
        let pressed = unsafe { (read_volatile(GPIOA_IDR) & (1 << 0)) == 0 };

        unsafe {
            if pressed {
                write_volatile(GPIOC_BSRR, 1 << (13 + 16)); // PC13 = 0 → 켜짐
            } else {
                write_volatile(GPIOC_BSRR, 1 << 13);        // PC13 = 1 → 꺼짐
            }
        }

        if pressed != was_pressed {
            info!("button {}", if pressed { "pressed" } else { "released" });
            was_pressed = pressed;
        }
    }
}
```

### 3-4. Rust HAL (embassy-stm32) — 버튼으로 LED 켜기

```bash
cargo add embassy-stm32 --features stm32f103c8,defmt
```

```rust
#![no_std]
#![no_main]

use cortex_m_rt::entry;
use defmt::info;
use embassy_stm32::gpio::{Input, Level, Output, Pull, Speed};
use {defmt_rtt as _, panic_probe as _};

#[entry]
fn main() -> ! {
    let p = embassy_stm32::init(Default::default());
    info!("button demo (HAL) start");

    let button = Input::new(p.PA0, Pull::Up);
    let mut led = Output::new(p.PC13, Level::High, Speed::Low);

    let mut was_pressed = false;
    loop {
        let pressed = button.is_low();
        if pressed { led.set_low(); } else { led.set_high(); }

        if pressed != was_pressed {
            info!("button {}", if pressed { "pressed" } else { "released" });
            was_pressed = pressed;
        }
    }
}
```

### 3-5. 한눈에 비교

| | C 레지스터 | C HAL | Rust 레지스터 | Rust HAL |
|---|---|---|---|---|
| 핀 설정 | 비트 직접 | CubeMX 클릭 | 비트 직접 | `Input::new(p.PA0, Pull::Up)` |
| 버튼 읽기 | `GPIOA_IDR & (1<<0)` | `HAL_GPIO_ReadPin` | `read_volatile(GPIOA_IDR)` | `button.is_low()` |
| LED 제어 | `GPIOC_BSRR = ...` | `HAL_GPIO_WritePin` | `write_volatile(GPIOC_BSRR, ...)` | `led.set_low()` |
| 위험 구역 표시 | 없음 | 없음 | `unsafe { }` 필수 | 없음 (크레이트 안에 숨음) |
| 비트 반전 연산자 | `~` | - | `!` | - |
| 로그 | UART + printf 연결 필요 | 동일 | `info!` (디버거 선 RTT) | `info!` |
| 빌드·굽기 | CubeIDE 빌드 + stmflash | 동일 | `cargo run --release` | 동일 |
| 칩이 바뀌면 | 주소·비트 전부 재확인 | 대부분 그대로 | 주소·비트 전부 재확인 | 대부분 그대로 |

Rust HAL의 핵심: `p.PA0`를 넘기면 소유권이 이동 → 같은 핀을 두 곳에서 쓰면 컴파일 에러.
C는 설정과 코드가 어긋나도 컴파일되고 실행해 봐야 앎.

연산자 우선순위 주의: Rust는 `&`가 `==`보다 먼저 계산되지만, C는 반대라 `x & 1 == 0`이 의도와 다르게 동작함. 양쪽 모두 괄호를 치는 습관이 안전.

## 4. 반바니에는 무엇으로?

- 기본은 HAL
    - 회로 재설계 중 칩이 바뀔 수 있음 → HAL이면 코드 재사용 가능
    - 다음 개발자가 읽을 수 있는 공통 언어 (업체 의존 탈출이 목적이므로 중요)
    - CubeMX가 초기화를 대신해 줘서 개발이 빠름
    - 약 분할기는 HAL 속도로 충분
- 레지스터/LL은 필요한 곳만
    - 아주 짧은 주기로 반복되는 코드 (모터 제어 인터럽트 등)
    - HAL이 지원하지 않거나 원하는 대로 안 되는 기능
    - 디버깅할 때 레지스터 값 직접 확인
- Spring 비유: 기본은 JPA, 성능이 중요한 쿼리만 네이티브 SQL
- Rust로 가도 구조는 같음: embassy-stm32 기본 + 필요한 곳만 직접 접근

## 5. 개발 환경 정리

| 도구 | 용도 | 비고 |
|---|---|---|
| STM32CubeIDE | C 코드 작성, 빌드 | 강사님 지정 버전 1.19.0 (2.x는 CubeMX가 빠짐) |
| STM32CubeMX 6.19 | 단독 핀 설정 도구 | CubeMX2는 C5/G5/H7P 전용이라 F103엔 안 맞음 |
| probe-rs | 굽기, Rust 실행·로그 | `cargo install probe-rs-tools --locked` (Rust 1.95 이상) |
| RustRover | Rust 코드 작성 | `cargo run --release`로 빌드·굽기·로그 한 번에 |

`~/.zshrc`에 추가한 굽기 함수:

```bash
stmflash() {
  local elf="${1:-Debug/$(basename "$PWD").elf}"
  probe-rs download --chip STM32F103C8 "$elf" && probe-rs reset --chip STM32F103C8
}
```

Rust 프로젝트 구성:

```
rust-tutorial/
├── .cargo/config.toml   # 타깃 thumbv7m-none-eabi, runner = probe-rs run --chip STM32F103C8
├── memory.x             # FLASH 64K @ 0x08000000, RAM 20K @ 0x20000000
├── Cargo.toml           # [[bin]] test = false, bench = false 추가
└── src/main.rs
```

## 6. 오늘 만난 문제와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| `Could not verify ST device! Abort connection` | CubeIDE가 칩을 정품 ST로 인정하지 않음 (호환 칩 가능성) | probe-rs로 굽기. 강사님 지정 1.19.0으로 재시도 예정 |
| OpenOCD로 바꿔도 굽기 직전에 종료 | CubeIDE 자체 정품 검사 | 위와 동일 |
| "계속 켜기" 코드를 구웠는데 LED가 깜빡임 | 블루필에 원래 있던 공장 테스트 프로그램이 돌고 있었음 (실제로는 안 구워짐) | 동작이 확실히 달라지는 코드로 검증하는 습관 |
| `cargo install probe-rs-tools` 실패 | Rust 1.94, 일부 의존성이 1.95 요구 | `rustup update stable` 후 `--locked`로 설치 |
| RustRover `Can't find crate for 'test'` | no_std라 테스트 프레임워크가 없음 (IDE 분석만의 문제) | `Cargo.toml`에 `[[bin]] test = false, bench = false` |
| Ctrl+C 후에도 LED가 계속 깜빡임 | 플래시에 구워진 상태, Ctrl+C는 로그 보기만 종료 | 정상. 지우려면 `probe-rs erase --chip STM32F103C8` |
| `'GPIO_LED' undeclared` | 라벨은 `GPIO_LED_Pin`, `GPIO_LED_GPIO_Port`로 생성됨 | 생성된 이름으로 사용 |
| CubeIDE 2.x에 .ioc 생성 메뉴 없음 | 2.0부터 CubeMX가 IDE에서 분리됨 | CubeMX 단독 사용 또는 1.19.0 설치 |
